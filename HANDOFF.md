# Sparkle Valley · Thung Lũng Lấp Lánh — Handoff

A bilingual (English / Tiếng Việt) 3D open-world browser game for the owner's children, aged 2–8.
Attach this file at the start of a new chat. Code: **https://github.com/nguyentuanphu/Sparkle-Valley** (work on a `claude/…` branch, merged into `main` by pull request).

---

## 0. Ground rules (the owner set these — follow them every time)

1. **Do not change, remove or restyle any existing feature or UI unless the owner asks for that change.** Layout, colours, fonts, icons, button order, menu tabs, Grown-ups sections, texts and game rules stay as they are. New work goes *alongside*.
2. **HARD RULE: never `git push`, and never open or update a pull request, until the owner has checked the work and clearly said to push.** Commit locally, report what changed and how it was tested, give the Netlify zip, then wait. One "yes, push" covers one push. (Also in `CLAUDE.md`.)
3. **Run the regression suite before and after every change** (§2). The `contract` check fails if the UI's structure changed; run `--update-contract` only when the owner asked for that UI change, and say so.
4. Every text is bilingual: `T('English', 'Tiếng Việt')`. Spoken lines: `say(en, vi)`. People's titles follow the language (`NAMES_EN` / `NAMES_VI`, `registerName()`); 3D signs take `['English', 'Tiếng Việt']` or a function and redraw on `onLang()`.
5. On every change **bump `VERSION` in `sw.js`** and add new files to `FILES`, or phones keep the old version.
6. **Never put API keys or personal data in the code or the repo.** Keys live only in the grown-up's settings on their device. The ElevenLabs key pasted in an early chat must be replaced after use.
7. **House number 8:** only the number "8" may appear. The street name must never appear in the game or the repo.
8. Test at phone (320–390 px), tablet and desktop sizes, with 1 and 2 players, in both languages, and say plainly what could not be tested.
9. Keep it fun and safe for ages 2–8, girls and boys. Under-5 mode never punishes (no losing, no timers, no reading needed); big kids can have real challenge.
10. **HARD RULES for land and roads (round 29, checked by `flat` and `roadshape`):** every village, town and city is one flat level (`LEVELS` in world.js, applied last in `heightAt`; only the river, the lake, ponds, bridge ramps, road surfaces and a building's own base pad differ). Roads are straight runs joined by true circular curves (fillets: asphalt 24 m, dirt 16 m), run straight into every gate, are never steeper than 10 % (dirt 14 %; a little more only where two fixed places are too close, then shared evenly), have every change of slope rounded, take the place's level inside a village and the through road's exact height at a junction, and have a soft verge with flowers along both sides. Never fill the river (bridge banks and road beds stay off it).
11. **Recorded Azure voices are always the voice.** Every new spoken line must end up in the pack: run `tools/voice-harvest.mjs` and `tools/make-voice-pack.mjs --engine azure` at the end of a round. The phone's own voice is only a fallback for a line with no recording.
12. **Test desktop and phone side by side every round** (`phone` check, plus screenshots at 390×760 touch and 1180×760 together). The owner found bugs on phones that desktop tests missed.
13. **No phone emoji in the look of the game:** any picture that shows on screen goes through `pic()` / `labelArt()` / `sprite()`, which draw the valley's own art from `js/art.js` (458 drawings, ~90 % of the emoji in the code). A new emoji needs a drawing there.

## 1. Run, deploy, install

- **Run:** `python3 -m http.server 8765` in the repo → http://localhost:8765. `window.__sv` is the game object (heroes, world, farm, partners, playGame…).
- **Netlify (main site):** `./build-netlify.sh` zips `index.html sw.js manifest.webmanifest netlify.toml css js fonts icons vendor videos content` (+ `voices/` if present). Drag the zip onto the **same** Netlify site's Deploys page. Saves belong to the web address, so a new "Netlify Drop" site starts empty.
- **GitHub Pages** auto-deploys `main` (`.github/workflows/pages.yml`). It needs a one-time setup: repo → Settings → Pages → Source: **GitHub Actions** (a run failed with "Get Pages site failed … Not Found" until this was done). For a private repo on a free plan, Pages is not available; use Netlify only.
- **Sparkle Studio (grown-ups' dashboard, Windows):** `studio/studio.cjs` is a small local web server (127.0.0.1:7777, no dependencies) with the dashboard in `studio/ui/`. `bash studio/build-exe.sh` packs both into `studio/dist/SparkleStudio.exe` (Node single executable, ~86 MB, marked a Windows GUI app so no console window; not in git: `studio/dist/`, `studio/.build/` are ignored). Put the exe in the game folder (or choose the folder in its Settings) and double-click: the dashboard opens in its own Edge/Chrome app window; ⏻ Close stops it, and it stops by itself 3 minutes after its window is closed. Messages go to `%APPDATA%\SparkleStudio\studio.log`. Pages: Home, Message, Villagers (names, photo faces, voice woman/man), Stories, Family quiz, **Map & building** (modes: villagers; build houses and buildings from `BUILD_TYPES` in `js/worldedit.js`, houses become visitable homes with a name and owner; move or remove anything inside a circle; flat land rectangles or grow a whole place; "show the buildings that are there now" opens the game out of sight and reads its buildings), **Real photos** (the best photos of every landmark from Wikipedia, Wikimedia Commons search and Openverse, a few from each, into `photos/` with credits and licences), **Ads** (off; pictures, words, link, where, how many a day, and a guide), **Defaults** (rest timer, language, bilingual, money, captions, calm, text size, music: applied once on each device whenever they change), Children (open/edit a `.txt` backup), Voices (count missing lines incl. `tools/voice-extra.json`; make them with Azure or Piper or the microphone; import a device's backup to add the lines it said with the machine voice), **Website** (Netlify deploys with which is live, rebuild, make an older deploy live again; GitHub latest commits and open pull requests with Merge), Publish (**to GitHub**: only changed files of `content/ voices/ photos/ tools/voice-extra.json`, one commit, Netlify then rebuilds; or the zip / Netlify upload), Check, Settings. Keys (Azure, Netlify, GitHub fine-grained token) live only in `%APPDATA%\SparkleStudio\settings.json`. Without the exe: `node studio/studio.cjs` (Node 22). Its backups of `content/custom.json` go to `content/old/` (ignored, never published).
- **How the live site updates:** Netlify site `sparklevalley` is linked to this GitHub repo and publishes `main` (PRs get deploy previews). So: merge a PR → live in a minute or two; Sparkle Studio's "Publish to GitHub" commits to `main` → live the same way. Devices pick up new files the next time the game opens online (service worker; content, voices and photos are kept for offline).
- **Family content pack:** `content/custom.json` (+ `content/faces/*.jpg`) is read at start by `js/custom.js`: daily message, names, faces, `genders`, own tales, family quiz, `npcs` (villagers placed on the map, spawned in `main.js`), `world` (`build`, `edits`, `land`: js/worldedit.js adds buildings before the homes are made and moves/removes after everything is built; `land` becomes FLATS in world.js), `defaults` (applied once per change, signature in `settings.packDefaults`). A device's own renames and settings always win. Written by the Studio; `{}` means nothing extra.
- **Phones:** close and reopen the app to pick up a new version. iPhone: play from the Home Screen icon (Safari may clear data of sites not opened for weeks). Backups to iCloud/Drive move progress between devices.

## 3. What the game has (keep all of it)

Outfits (dress, shirt & shorts, áo dài, tunic, overalls, hoodie), hair, skin, hats (crown, cap, bunny ears, flower, bow, nón lá, earned passport hats), wings or cape, gliders, the whistling kite. Photo editor with drag, pinch and circle crop. 1 player, 2 on one screen (split: side by side in landscape, stacked in portrait; shared farm and coins), or online with friends.

**World** (400 × 400, x east, z south):

**Online play** (`net.js`, `relay.js`):
- Rooms of up to 6 with a 4-digit code; the starter relays messages (star). Direct links via PeerJS/WebRTC with live voice; when the direct link can't open (different networks), the **cloud relay** carries the room through free public MQTT brokers (emqx, hivemq, mosquitto, eclipse — all at once, copies dropped), encrypted AES-GCM with a key from the room code, hashed topics.
- **Photos** cross the cloud relay with a second lock: each pair of players agrees a private ECDH key, so only the friend it is meant for can open it (a 112 px JPEG, sent once per friend).
- The starter introduces every newcomer to everyone (direct and cloud), so in rooms of 3+ everybody sees everybody. Positions are sent on their own clock (10 a second, once a second while a menu or game is open or the app is in the background), so slow phones still keep friends up to date.
- Friend codes, friend status (🟢 online · place · room with ▶ Join, ⚪ offline · how long ago), invites, signal bars + ping + route per friend, wake lock, auto switch-over, "Find / walk / fly / ask to come", trading, removing a player. Voice needs a direct link or a grown-up's own TURN relay.

**For grown-ups** (press and hold; also from ⚙️ quick settings in the game): players, backup/restore (`.txt` via share sheet → iCloud/Drive), language, AUD/VND, sound/music, voices (device, ElevenLabs, Microsoft Azure, Google, family recordings, offline voice pack), captions, text size, calm mode, rain, festival picker, rest timer, camera mode, graphics, credits page, renaming characters (and giving any villager a **photo face**: 📷 in Character names opens a circle cropper; the photo goes on their face and their skin takes the colour sampled from the photo so it blends in; `nameAvatar`/`applyNpcFaces` in `avatar.js`, saved in `settings.npcFaces`), coins top-up, online play (friend codes, TURN relay, connection test), voice control, optional AI villager chat (Anthropic key; model `claude-opus-5-5`).

**Progress is never lost:** saves in localStorage, mirrored a few seconds later to IndexedDB (`sparkle-valley-save`: latest + one per day) and the `sv-save` cache; restored automatically if the main save disappears; `navigator.storage.persist()` requested. Updates only replace the game's own cache; the voice pack (`sv-voices`) and `sv-save` are kept.

**Voice pack:** cast English & Vietnamese woman + man, Chinese & Hindi man. 5,124 files, ~290,290 characters (≈ 85 MB) ≈ 111,000 ElevenLabs credits (Flash v2.5) or ≈ US$3.56 on Azure (free F0 tier: 500k chars/month, so it fits in one free month; the tool paces ~18 requests/min, about 4 hours). `node tools/make-voice-pack.mjs --engine azure --count` shows the cost without a key. The pack is matched to the exact sentences, so make it from the latest `main`; after later rounds run it again and it only makes the new lines. The game downloads the whole pack once and keeps it offline.

**Why a line can still use the machine voice, and how it is fixed:** the pack only has sentences known before playing. Lines built while playing (names, numbers, colours, items: 171 of the 302 places that speak) are collected by `node tools/voice-harvest.mjs` (plays every game and taps everything in both languages, writes `tools/voice-extra.json`), and by each device: a line said without a recording is noted (`sv2_voicemiss`, shown in Grown-ups → Voices, carried in the backup file, imported in Studio → Voices). `make-voice-pack.mjs` and the Studio include `voice-extra.json`. When a whole line has no recording, its recorded sentences still play from the pack and only the rest uses the device voice (`speak` in `js/voice.js`). Women, girls and grandmas use the woman's recording, men, boys and grandpas the man's (`speakerKind`: titles in both languages, girls' names, Studio genders). On iPhone the game asks for the "playback" audio session, so recordings are not silenced by the silent switch (the device voice ignores that switch, which is why only the machine voice was heard there).

**Making the Azure voice pack, step by step:**
1. Azure portal → Microsoft Foundry → Speech service → **Create**: new resource group `sparkle-valley`, region **Australia East**, a unique name, pricing tier **Free F0** (or Standard S0 if F0 is taken). Review + create → Go to resource → **Keys and Endpoint** → copy KEY 1 and the region (`australiaeast`).
2. **In a Claude Code cloud session:** the environment needs Network access → Custom with `australiaeast.tts.speech.microsoft.com` and `australiaeast.api.cognitive.microsoft.com` allowed (default package managers kept), and environment variables `AZURE_SPEECH_KEY` (KEY 1) and `AZURE_SPEECH_REGION=australiaeast`. Both only reach sessions started after the change. Never paste the key into chat or commit it.
3. **On your own computer instead:** install Node.js LTS, download the repo (Code → Download ZIP), open a terminal in the folder and run `node tools/make-voice-pack.mjs --engine azure --key <KEY 1> --region australiaeast` (keep the computer awake; on a Mac put `caffeinate -i ` in front). If it stops, run it again: it skips finished files. 401 = wrong key or region.
4. The pack lands in `voices/` (`en`, `vi`, `zh`, `hi`, `manifest.json`). `./build-netlify.sh` includes it, or copy `voices/` next to `index.html` in the unzipped Netlify folder, then upload.
5. On each device: ⚙️ → Grown-ups → 🎙️ Offline voice pack shows "Installed"; tap **Keep all voices on this device** once on Wi-Fi. Leave Voice engine on "This device": recorded lines play first, anything missing uses the device voice.
6. Live Azure voices without a pack: Grown-ups → ✨ More natural voice → Voice engine **Microsoft Azure**, paste KEY 1 and the region, test with ▶ English / ▶ Tiếng Việt. The key stays on that device only.

## 7. Decisions and known limits

- Natural voices, voice cloning and AI chat are optional, online and use the parent's own keys; everything works offline without them.
- Online play uses the public PeerJS server to introduce devices; voice goes directly; game messages fall back to the cloud relay. The relay key comes from the 4-digit room code, so names and positions are only lightly protected from someone who knows the scheme; photos have their own pair lock (ECDH). Anyone who joins a room is a player and appears in the room list; the room's starter can remove them (works on both routes, and they can't come back into that room). Only the starter can say "full" or remove someone; ids, looks, friend codes and positions from others are checked before use (they go into the page). Topic names use a slow hash so friend codes can't be read back from them. Worth considering if the owner wants it: the starter approving each newcomer, and longer room codes.
- Graphics follow the setting (Fast / Auto / Pretty); Auto picks Fast on phones and then raises the sharpness step by step while the phone keeps up (adaptive resolution, `adaptResolution` in `main.js`).
- iOS Home Screen apps keep storage separate from Safari: use backups to move progress.
- Stamina is counted in wheels (1–3); food and juice give one extra wheel.
- Saves: if the main save is missing and its copy can't be read within 8 s, this session never overwrites the copies (new progress goes to `new-…`), and the restore also looks at the daily copies (the last 10 are kept).
- **Level land grows by itself:** every building, house, kiosk and landmark gets a level footprint (`FOOTPRINTS`, filled by `levelUnderBuildings` after the world is built), and `widenFlatLand` widens every flat (`WIDE` = 10 m) at the very end, moving the ground, trees, roads and props up or down with it so nothing shifts on the map. World building places things with `oldHeightAt` (the heights before widening), so adding a new building only needs it placed: its ground levels itself.
- Inside the cloud sandbox, Node's `fetch` needs `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` for the voice-pack tool (otherwise Azure answers 403).
- **Roads and the river:** roads.js `profile()` works out each road's height (fixed parts: bridge decks, village levels, gate ends, junction overlaps; long average; grade limit; rounding) and registers road beds; `heightAt` shapes the ground under and beside each road to it (wider banks for deeper cuttings), so walking on a road is walking on the ground (`world.roadTop` is null). `world.roadLines` keeps every road's points and heights (tests, verges, flowers). The river line is `RIVER` in world.js (ferry.js uses the same).
- **Village games time (js/folkshow.js):** the folk-game hosts of each village take turns on the real clock (150 s slots, 75 s of play), a board counts down, 3 coins start the next game now; a few children dance round the host; one singer per village (bird stage names, renameable) sings traditional songs on the synthesiser with the words in a bubble.
- **Boats:** the lake ferry and the river raft line (up and down the river past the towns, under both bridges) ask "Where to?" and go straight there; the two crossing rafts go to the other bank. While on a boat the camera stays under bridge decks.
- **Friends meet by themselves:** `G.autoMeet` (main.js): with friends on the list and sharing on (switched on by adding a friend), the friend whose code comes first opens a room and the other joins it from their status. Grown-ups → Online play can switch it off.
- **Ads (js/ads.js):** nothing unless `content/custom.json` has `ads.enabled: true` (Sparkle Studio → Ads, with a guide). Signboards near towns and a small card after a mini-game, labelled, no tracking, links behind a grown-up sum. **Hip roofs:** `P()` in gfx.js turns a 4-sided cone before stretching it, so a long building's roof stays square on its walls.
- Leafy spots, shrines and towers are fixed in `world.js`; heritage sites, crops and culture groups find a clear spot (off roads) near their village by themselves.
